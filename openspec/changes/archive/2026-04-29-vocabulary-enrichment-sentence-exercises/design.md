## Context

Vocabulary items are currently stored as flat `(hebrew, english, audio_url)` tuples with usage-tracking columns. There is no grammatical metadata, no semantic structure, and no sentence generation. Exercises are limited to isolated word flashcards (English → type Hebrew). The app needs two new exercise surfaces — theme-based sentence translation and verb conjugation drills — both of which require richer word metadata and LLM-assisted generation.

pgvector is already enabled on the Supabase project. The existing word extraction flow (`POST /api/lessons/[id]/words`) already calls an LLM to parse lesson photos; tagging can piggyback on this call.

## Goals / Non-Goals

**Goals:**
- Store POS, gender, binyan, and present-tense conjugations on vocabulary items; AI-assigned at extraction, student-editable in UI
- Store 1536-dim embeddings on vocabulary items (english gloss) and theme descriptions for vector similarity search
- `themes` table: pre-seeded with 6 themes, user-extensible; each theme has a pre-computed embedding
- `generated_sentences` table: LLM-generated exercises persisted only on student rating; feedback injected into future prompts
- Sentence practice mode: theme picker → vector retrieval → LLM generation → translate English to Hebrew → rate
- Phrases (`pos = 'phrase'`) surface in flashcards (standalone) and in sentence exercises (embedded in LLM-generated context)

**Non-Goals:**
- Retroactive tagging of existing vocabulary items (migration runs for embeddings only; POS/gender/binyan left null on existing rows)
- Past/future tense conjugation exercises (conjugations JSONB is structured to support them later; only present tense populated now)
- Multi-student / per-user data isolation (single-student app)
- Verb conjugation exercise UI (schema supports it; exercise UI is out of scope for this change)

## Decisions

### D1: AI tagging at extraction time, not in a background job

Tags and embeddings are computed during `POST /api/lessons/[id]/words` using a single LLM call that returns pos, gender, binyan, infinitive (if input is conjugated), and present-tense conjugations. A separate synchronous call to the Supabase embedding Edge Function computes the embedding before the row is written. The student reviews tags on the lesson detail page afterward.

**Alternatives considered:** async database webhook pattern (Supabase's recommended approach for bulk use) — rejected because themes need their embedding available immediately after creation; using a consistent sync pattern across vocabulary items and themes is simpler to reason about.

### D2: Embed the English gloss using Supabase's built-in gte-small model (384 dims)

Embeddings are generated by calling a Supabase Edge Function that uses `Supabase.ai.Session('gte-small')` — a 384-dimension model that runs natively in the Edge runtime with no external API dependency, fits entirely within the free tier (500K invocations/month), and scores 61.36 on MTEB vs OpenAI text-embedding-3-small's 62.26 — negligible quality difference at this vocabulary scale.

All `vector(...)` columns are `vector(384)`. The English gloss is embedded (not Hebrew) for the same reasons: unambiguous text, same vector space as theme descriptions.

**Alternatives considered:** OpenAI `text-embedding-3-small` (1536 dims) — rejected because it adds an external API cost and dependency when Supabase's native model is free and sufficiently accurate.

### D3: No explicit topic tags — vectors handle categorization

Rather than maintaining a taxonomy (time/location/food/etc.) as tag columns, the theme-based retrieval uses vector similarity: embed the theme description, find the nearest vocabulary items. This requires zero manual tagging beyond what AI assigns at extraction. Themes are user-extensible without schema changes.

**Alternatives considered:** `tags text[]` column — rejected because it requires maintaining a taxonomy and manual assignment; vectors give the same retrieval with less friction.

### D4: JSONB for conjugations — tense keys, array values

Each tense is an ordered 9-element array. Pronoun order is a fixed app-level convention: `[ani, ata, at, hoo, hee, anahnoo, atem, hem, hen]` (indices 0–8), defined once as a constant and used by all exercise UI. No key names in the JSON — position implies pronoun.

```jsonc
// present (now)
{ "present": ["כותב", "כותב", "כותבת", "כותב", "כותבת", "כותבים", "כותבים", "כותבים", "כותבות"] }

// past/future added later
{
  "present": ["כותב", "כותב", "כותבת", "כותב", "כותבת", "כותבים", "כותבים", "כותבים", "כותבות"],
  "past":    ["כתבתי", "כתבת", "כתבת", "כתב", "כתבה", "כתבנו", "כתבתם", "כתבו", "כתבו"]
}
```

JSONB allows tenses to be added without schema migrations. Only `present` is populated in this change.

**Alternatives considered:** pronoun-keyed object (`{ "ani": "כותב", ... }`) — rejected as verbose with no benefit; separate `verb_conjugations` table — premature normalization for data always read with its parent word.

### D5: Root (שורש) stored as a plain text column

A `root text` nullable column on `vocabulary_items` stores the Semitic root letters (e.g. `כתב`, `הלכ`, `שוק`). Populated by AI at extraction time for verbs and nouns; NULL for phrases, conjunctions, adverbs where root is not meaningful. The root is the foundation for future word-family linking — words sharing a root form a cluster (כותב, כתיבה, מכתב all share `כתב`). Plain text is sufficient; no separate table needed until word-family exercises are built.

### D6: Generated sentences stored only on rating; rating is NOT NULL

Sentences exist in memory during the exercise. On thumbs-up or thumbs-down, the sentence is INSERT-ed with `rating` set. Unrated sentences are discarded. This keeps the table clean and ensures every stored sentence has a quality signal.

`rating` column: `text NOT NULL CHECK (rating IN ('up', 'down'))`.

### D6: LLM declares which item_ids it used

The LLM response includes `used_item_ids: uuid[]` alongside `english` and `hebrew`. This avoids fragile post-hoc matching against morphologically-inflected Hebrew text. At generation time, the prompt instructs the LLM to return the IDs of vocabulary items it incorporated.

### D7: Feedback injected into prompt, not used for fine-tuning

Past rated sentences are retrieved for the same theme and formatted as examples in the system prompt. Thumbs-down sentences with feedback text are the strongest signal. No fine-tuning pipeline is needed.

### D8: theme_id FK with ON DELETE SET NULL on generated_sentences

If a theme is deleted, its associated sentence feedback is retained (orphaned with `theme_id = NULL`) rather than cascaded away. Historical feedback has research value even if the theme is removed.

## Risks / Trade-offs

- **Embedding cost at extraction time** — each word insert makes an OpenAI embedding API call. At low volume this is negligible (~$0.00002/word). At scale, batch embedding would be cheaper. → Acceptable for now; can batch retroactively.
- **LLM tagging errors** — AI may misassign POS (especially for ambiguous unpointed Hebrew). → Student review UI on lesson detail page provides a correction path. Errors affect exercise quality but not correctness.
- **Small vocabulary at launch** — vector search over 20–50 words may not cluster meaningfully by theme. → The sentence LLM can still generate good exercises; retrieval quality improves as vocabulary grows.
- **ivfflat index requires minimum row count** — `ivfflat` index needs ~100+ rows to be effective; on small datasets a sequential scan is used automatically by pgvector. → No action needed; index created now, effective later.
- **Phrase embedding quality** — Short phrases like "איזה כיף" embed to reasonable positions in English space ("so fun" → near emotion/exclamation cluster). Acceptable for retrieval purposes.

## Migration Plan

1. Wipe database and run fresh migration: create enums, full `vocabulary_items` schema with all new columns, `themes`, and `generated_sentences` tables; create ivfflat indexes.
2. Seed `themes` table with 6 initial themes + pre-computed embeddings (one-time script).
3. Deploy updated word extraction API; all words get full tagging from the start.
4. Deploy sentence practice UI.

**Rollback:** restore from pre-wipe snapshot.

**Rollback:** columns are additive (nullable); new tables can be dropped; no existing API behavior changes.
